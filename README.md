# meshthingy v0

A Meshtastic-compatible LoRa mesh node built around an ESP32-S3 and an Ai-Thinker
HT-RA62 (RA-01SH) LoRa module, with GPS, OLED, environmental and motion sensing,
and USB-C Li-Ion charging.

KiCad project name: `meshtastic-v0` — open [meshtastic-v0.kicad_pro](meshtastic-v0.kicad_pro).

## Status

Schematic and layout are complete and routed. No known electrical defects —
every remaining ERC message is an annotation or an intentional design choice,
documented under [Known issues](#known-issues).

| Check | Result |
| --- | --- |
| DRC (`--severity-all`) | 0 violations, 0 unconnected pads |
| Schematic parity | 2 cosmetic field mismatches |
| ERC (`--severity-all`) | 6 errors, 14 warnings — all explained below |

Before ordering, read [Assembly notes](#assembly-notes) — **JP3 and JP4 must be
bridged or the display has no power.**

## Known issues

Run the checks yourself with the commands below before trusting this list.

**The 6 remaining ERC errors, and why each is not a defect**

| Error | Explanation |
| --- | --- |
| `U1` pins 1 & 2 not driven | The OLED's supply and ground reach it through the 3-way solder jumpers `JP3`/`JP4`. ERC cannot trace through a jumper, so it sees the pins as undriven. Intentional — see [Assembly notes](#assembly-notes). |
| `#PWR020` (`+3V3`) not driven | `+3V3` is generated by the `U3` buck and reaches the rail through inductor `L2`, so ERC sees only passives. Add a `PWR_FLAG` to silence. |
| `#PWR02` (`GND`) not driven | No pin in the design is typed as a ground *source*. Add a `PWR_FLAG` to silence. |
| `U6` pin 13 (`VBUS`) not driven | `VBUS` comes from the USB-C receptacle, whose pins are typed passive. Add a `PWR_FLAG` to silence. |
| `U7` pin 24 (`IO47`) not connected | Genuinely unconnected ESP32-S3 GPIO. Add a no-connect flag if that's deliberate. |

Adding three `PWR_FLAG` symbols (`+3V3`, `GND`, `VBUS`) and one no-connect flag
would bring ERC to zero errors. None of this changes copper.

**Worth reviewing**

- Several DRC checks are set to *ignore* in the project settings, including
  silkscreen clearance/overlap, missing courtyard, and text height/thickness.
  The clean DRC result does not cover these.
- Per-rail labels (`GPS_VDD`, `LORA_VDD`, `ACCEL_VDD`, `BME_VDD`, `3V3`) are all
  electrically merged into `+3V3`. **This is intended** — the local labels are
  documentation only, and the resulting `multiple_net_names` ERC warnings are
  expected. There is one `+3V3` rail.
- BOM rows carry no MPN or manufacturer, so the BOM is not yet orderable.
- Three `lib_symbol_mismatch` warnings (`U3`, `C13`, `LS1`) mean the schematic's
  embedded symbol cache has drifted from the library files. Update from library
  in Eeschema when convenient.
- The 2 remaining schematic-parity messages are cosmetic metadata only: an empty
  `Description` on `R22` and a missing `Sim.Pins` field on `D2`. Neither affects
  fabrication.

## Assembly notes

**`JP3` and `JP4` must be bridged before the display will work.** Both are
`SolderJumper_3_Open` — three-way jumpers with *no* pads bridged as fabricated.
They select which of the OLED's two power pins gets `+3V3` and which gets `GND`,
so the same footprint accepts modules with either the VCC/GND or GND/VCC pinout.

For each jumper, pin 1 is `+3V3`, pin 3 is `GND`, and the centre pin 2 goes to the
module. Bridge centre-to-1 on one jumper and centre-to-3 on the other, matching
the pinout printed on the display module you actually source. Bridging both
jumpers to the same rail, or bridging all three pads on either, shorts `+3V3`
to `GND`.

`JP1` and `JP2` are 2-way `SolderJumper_2_Open` jumpers, also unbridged as
fabricated.

## Checks and outputs

```bash
kicad-cli sch erc  --severity-all --output erc.rpt meshtastic-v0.kicad_sch
kicad-cli pcb drc  --severity-all --schematic-parity --output drc.rpt meshtastic-v0.kicad_pcb

kicad-cli pcb export gerbers --output fab/ meshtastic-v0.kicad_pcb

kicad-cli sch export bom     --output bom.csv meshtastic-v0.kicad_sch
```
